\section{Penugasan dan Hasil}
Selama pelaksanaan kerja praktik pada \PeriodeKP, penugasan penjaminan kualitas difokuskan pada perancangan skenario, implementasi skrip otomatisasi pengujian, serta verifikasi keandalan fungsional dan keamanan sistem pengelolaan alur kerja. Pengujian dilakukan secara independen terhadap antarmuka dan layanan aplikasi yang dikembangkan oleh tim pengembang.

\subsection*{Lingkup Penugasan dan Jenis Pengujian}
Penugasan penjaminan kualitas mencakup pengujian fungsionalitas, validasi masukan, interaksi antarmuka pengguna, serta keamanan akses data pada empat kelompok fitur utama:
\begin{enumerate}[label=\arabic*)]
\item \textbf{Dasbor Pemantauan dan Analitik}: Memeriksa penyajian metrik pemantauan pekerjaan, akurasi diagram donat sebaran data, kartu indikator tahapan alur kerja, ringkasan permohonan, efektivitas capaian SLA, grafik distribusi tahapan, serta metrik evaluasi KPI berkala.
\item \textbf{Pengelolaan Data Master}: Menguji operasi pembuatan, pembacaan, pembaruan, dan penghapusan (\textit{CRUD}) serta integritas aturan validasi pada master peran pengguna (\textit{role}), master akun pengguna (\textit{user}), master unit dan divisi organisasi, konfigurasi sistem, serta data referensi operasional.
\item \textbf{Koleksi Proses Bisnis}: Memeriksa tabel koleksi proses bisnis, filter parameter, pencarian tiket alur kerja, dan pembukaan rincian riwayat tahapan pekerjaan.
\item \textbf{Autentikasi dan Notifikasi}: Memverifikasi proses masuk dan keluar pengguna, pengelolaan sesi peramban, penolakan akses rute tanpa kredensial sah, serta pemutakhiran status penandaan notifikasi dalam aplikasi.
\end{enumerate}

Pengujian menerapkan pendekatan kotak abu-abu (\textit{greybox testing}) yang mengombinasikan skenario kebutuhan bisnis dengan analisis kode sumber untuk mengenali rute layanan, struktur muatan data, dan penanda elemen antarmuka (\textit{data-cy}). Pengujian dibagi menjadi dua tingkatan, yaitu pengujian antarmuka ujung ke ujung (\textit{end-to-end}) berbasis peramban dengan pola \textit{Page Object Model} (POM) dan pengujian langsung ke antarmuka pemrograman aplikasi (\textit{API testing}) untuk memverifikasi fungsionalitas CRUD, batas latensi respons di bawah dua detik, serta pemeriksaan celah otorisasi.

\subsection*{Temuan dan Tindak Lanjut}
Rangkaian pengujian otomatis yang dijalankan berhasil mengidentifikasi sejumlah anomali teknis dan perbedaan perilaku implementasi:
\begin{enumerate}[label=\alph*)]
\item \textbf{Celah Otorisasi Endpoint Layanan}: Pengujian API pada rute pengelolaan peran menemukan bahwa layanan belum menerapkan middleware otorisasi berbasis peran (\textit{Role-Based Access Control}). Pengguna dengan token berhak rendah dapat melakukan pemanggilan manipulasi data secara langsung. Temuan ini didokumentasikan sebagai rekomendasi pengetatan otorisasi di sisi peladen.
\item \textbf{Penamaan Selektor Pengujian Dinamis}: Pada komponen tabel terpadu, tombol penyaring menerapkan atribut selektor dinamis yang bergantung pada parameter modul, sementara sel menu aksi pada tabel master peran belum dilengkapi atribut pengujian khusus. Skrip otomatisasi disesuaikan dengan penelusuran struktur simpul tabel sebelum standardisasi atribut diterapkan pengembang.
\item \textbf{Penanganan Peristiwa Navigasi Menu Konteks}: Pada antarmuka proses bisnis, komponen menu konteks hanya mengeksekusi perpindahan halaman saat menerima aksi klik langsung peramban, sedangkan simulasi penekanan tombol Enter pada elemen daftar tidak memicu pustaka perutean. Skrip pengujian diselaraskan dengan menargetkan tautan aksi secara langsung.
\item \textbf{Perilaku Validasi Komponen Masukan Komposit}: Komponen kata sandi membungkus masukan dalam elemen kontainer div, sehingga status keabsahan HTML5 (:invalid) tidak melekat pada pengenal terluar sebagaimana komponen teks biasa. Skrip pengujian diarahkan secara spesifik ke elemen masukan internal.
\end{enumerate}

Seluruh temuan dicatat dalam dokumen pelacakan pengujian dan dikomunikasikan secara berkala kepada tim pengembang serta pembimbing teknis dalam pertemuan koordinasi rutin untuk ditindaklanjuti.

\subsection*{Hasil yang Dapat Dibuktikan}
Luaran nyata dari kegiatan penjaminan kualitas selama kerja praktik meliputi:
\begin{enumerate}[label=\arabic*)]
\item Tersedianya repositori kerangka kerja otomatisasi pengujian berbasis Cypress yang mencakup 23 berkas spesifikasi pengujian antarmuka dan API terstruktur.
\item Komponen pembantu otomasi berbasis Page Object Model yang dapat digunakan kembali, termasuk \textit{TableHelper} untuk tabel data terpadu dan pembantu interaksi navigasi.
\item Kumpulan skenario pengujian fungsional dan pengujian kasus negatif yang diselaraskan dengan dokumen spesifikasi kebutuhan alur kerja.
\item Lembar kerja induk (\textit{mastersheet}) pengujian dan pelaporan hasil uji yang dikelola secara terpusat pada media penyimpanan kolaboratif internal perusahaan (Microsoft SharePoint), memuat matriks skenario, status eksekusi, serta pelacakan temuan untuk koordinasi tim.
\item Pelaporan hasil pengujian terotomatisasi dalam format HTML dan JSON menggunakan Mochawesome Reporter, dilengkapi perekaman tangkapan layar dan video saat terjadi kegagalan untuk memfasilitasi diagnosis regresi.
\end{enumerate}
